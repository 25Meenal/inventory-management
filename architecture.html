Inventory Management System Architecture

Tech Stack

Frontend
Vue 3 + Composition API + Vite
Port: 3000
Backend
Python FastAPI + Pydantic
Port: 8001
Data Storage
JSON files (in-memory mock data)
No database

System Architecture

The system is a full-stack factory inventory management application with in-memory mock data storage, centralized filtering, and RESTful API.

Data Flow

Data Flow: User Interaction (Vue Component) ↓ useFilters() composable (selectedPeriod, selectedLocation, selectedCategory, selectedStatus) ↓ FilterBar components updates global filter state ↓ API call from client/src/api.js with filter params ↓ FastAPI endpoint receives query parameters ↓ apply_filters() + filter_by_month() functions transform data ↓ Pydantic models validate response ↓ JSON response back to frontend ↓ Refs hold raw data (allOrders, inventoryItems, etc.) ↓ Computed properties derive filtered/formatted data ↓ Vue template renders with reactivity

Key Components

Frontend

  • Views: Dashboard, Inventory, Orders, Demand, Spending, Backlog, Reports
  • Components: FilterBar, Modals (ProductDetail, InventoryDetail, etc.), LanguageSwitcher
  • Composables: useFilters (global filter state), useAuth, useI18n
  • API Client: api.js (centralized Axios calls)

Backend

  • Main: main.py (FastAPI app, endpoints)
  • Data: mock_data.py (loads JSON files)
  • Models: Pydantic models for validation

API Endpoints

Endpoint Method Filters Purpose
/api/inventory GET warehouse, category Get inventory items
/api/orders GET warehouse, category, status, month Get orders
/api/dashboard/summary GET All filters Summary statistics
/api/demand GET None Demand forecasts
/api/backlog GET None Backlog items
/api/spending/* GET None Spending data

Filter System

Centralized filtering with 4 global filters:

  • Time Period: All, Q1-2025 to Q4-2025, or specific months
  • Warehouse: All, San Francisco, Tokyo, Berlin
  • Category: All, Circuit Boards, Sensors, Actuators, Controllers
  • Order Status: All, Delivered, Shipped, Processing, Backordered
